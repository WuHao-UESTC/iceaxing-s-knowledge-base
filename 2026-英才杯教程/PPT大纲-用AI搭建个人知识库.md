# 用 AI 搭建你自己的知识库 —— 给大一新生的三把钥匙

> 讲授大纲 · 面向英才科协新生 · 素材全部取自本知识库真实结构
> 三个角度：**项目架构（放哪怎么连）→ 工作流（怎么持续产出）→ 约束文件（怎么让 AI 不跑偏）**

---

## 0. 讲前准备（不讲，给讲者）

**一句话说清这门课**：今天不教你怎么记笔记，教你**怎么建一座能自己长大的知识城**——包括画城图（架构）、定施工流程（工作流）、立城规（约束文件）。

**核心类比（贯穿全场）**：知识库 = 一座城市。
- **架构** = 城区规划（哪些区、路怎么连、市中心在哪）
- **工作流** = 施工流程（谁来盖、按什么顺序盖）
- **约束文件** = 城规建筑法（层高多少、不许乱搭）

AI 在这个类比里是**施工队**——力气大、手艺好、但完全不认识这座城。你不给图纸、不给流程、不给法规，它盖出来的就是违章建筑。

**素材出处（现场可截图）**

| 讲页 | 素材来源 |
|---|---|
| 全库总览 | 仓库根目录（`IC/` `Communication/` `Digital Design/` …） |
| 索引中枢 | `IC/知识导图.md`（1200 行，L0–L4 结构） |
| 跨域关联标注 | 同上第 108–112 行（`⚡` `→` `↔` 真实用例） |
| 教材库模式 | `IC/`（子文件夹 = 教材） |
| 扁平工具库模式 | `IELTS/口语语料库/`（`万能工具箱.md` 共用件） |
| 约束文件 | `IC/CLAUDE.md`(418 行)、`Digital Design/CLAUDE.md`(373 行) |
| 工作流原文 | `IC/CLAUDE.md`「写笔记前的上下文准备」 |
| 自动化证据 | `git log`（`vault auto-sync (study.ps1)`） |

**时长建议**：36 页，讲 45 分钟 + 15 分钟答疑。
**现场演示（强烈建议）**：打开 `IC/知识导图.md` 的 Markmap 渲染视图——学生看到"纯 Markdown 变成可点击思维导图"那一刻，全场注意力就抓住了。

**一条贯穿全场的纪律**：每个内容页 = **一句话结论 + 一张真实截图 + 一句"大一能照做的事"**。

## 第一部分：开场（第 1–5 页）

### 第 1 页 · 封面
**主标题**：用 AI 搭建你自己的知识库
**副标题**：架构 · 工作流 · 约束文件
**视觉**：`IC/知识导图.md` 渲染出的 Markmap 思维导图截图（先震撼，不解释）

### 第 2 页 · 先分清：笔记 ≠ 知识库
```
散落的笔记            知识库
─────────           ─────────
一堆 .md 文件   →    文件之间有链接
按时间堆放      →    按结构组织
找不到 = 白写   →    顺着一张图能走到底
AI 帮不上忙     →    AI 接手就能干活
```
**结论**：**知识库的分界线在"有没有结构"，不在"写了多少字"。**
**讲法**：你手机相册里有一万张照片，那不叫作品集。

### 第 3 页 · 你的真实困境
> "我也记笔记。但期末复习时，我翻不到；写作业时，我想不起自己学过什么。"

**结论**：**问题不是记得少，是记得散。** 而 AI 恰恰最擅长处理"有结构"的东西，最不擅长处理"散"的东西。
**讲法**：同样是"帮我复习差分放大器"，对着散笔记 AI 只能瞎编；对着有导图的知识库，AI 能直接说出它和电流镜、和 cascode 的关系。

### 第 4 页 · 为什么现在搭，以及为什么用 AI
| 你的付出 | 传统笔记 | AI + 知识库 |
|---|---|---|
| 整理归类 | 手工，最枯燥 | AI 按规则自动归位 |
| 建立联系 | 想不起来就没建 | AI 主动搜全库找关联 |
| 维护索引 | 最容易烂尾 | 写完即回填，自动维护 |
| 复用旧知识 | 靠记忆 | 顺导图和链接走 |
**结论**：AI 承担了"**整理与关联**"这份最耗人、最容易烂尾的工作——这才是知识库能活下来的原因。

### 第 5 页 · 本场地图
```
              知识库的三根支柱
   ┌──────────────┬──────────────┬──────────────┐
   │  项目架构     │   工作流      │  约束文件     │
   │  放哪 · 怎么连│  怎么持续产出 │  AI 的规矩    │

```
**结论**：**架构让它不塌，工作流让它长大，约束文件让它不歪。** 三根柱子缺一根，库就烂尾。

### 第 8 页 · 命名规范：为什么值得较真
**素材**：本仓库真实命名规则（`IC/CLAUDE.md` 的「规则」）
- 子文件夹命名：`作者-书名简称`（无作者则直接用书名）
- 论文放入 `Papers/`，命名 `作者-年份-主题.md`
- 同一概念多本书时，链接前标注来源：`Razavi: 阻性负载 CS`
**结论**：**命名是给未来的你和 AI 看的**，不是给你自己省事。
**讲法**：`新建文件夹 (3)` 和 `Razavi-模拟CMOS集成电路设计`，三个月后哪个你还认得出？

### 第 9 页 · 索引中枢：知识库的市中心 ★
**结论**：每个学科建**一份** `知识导图.md`，它是全库唯一的"目录"。
**素材**：`IC/知识导图.md` 开头两行原文
```
> 概念索引中枢。L1 知识域 → L2 子域 → L3 具体概念 → L4 笔记链接。
> 笔记撰写后由 AI 自动维护 L4 链接和跨域关联标注。
```
**讲法**：为什么必须有它？因为**你（和 AI）每次动手前，都需要先知道"这东西在整个体系里的位置"**。没有市中心，每篇笔记都是孤岛。

### 第 10 页 · 零语法的思维导图：纯 Markdown 标题 ★
**素材**：`IC/CLAUDE.md` 的层级表
| 层级 | Markdown | 含义 | 真实示例 |
|---|---|---|---|
| L0 | `#` | 根节点 | `# IC 知识体系` |
| L1 | `##` | 知识域 | `## 基本放大级` |
| L2 | `###` | 子域 | `### 共源级 (CS)` |
| L3 | `####` | 具体概念 | `#### 阻性负载 CS` |
| L4 | `- [[wikilink]]` | 笔记链接 | 见下一页 |
**结论**：**你不用学任何新软件、新语法。** 就是 Markdown 标题，装个 `obsidian-markmind` 插件，它自动渲染成可折叠、可点击的思维导图。
**讲法**：这是本场最"啊哈"的一页。增删概念 = 增删一个 `####` 标题，零成本。

### 第 11 页 · L4 长什么样：链接 + 关联标注 ★
**素材**：`IC/知识导图.md` 第 108–112 行**原文**
```markdown
#### 源极退化 CS
- [[C3.单级放大器#3.3.6 源极退化的共源级|Razavi: 源极退化 CS]]
- ⚡ Gm 线性化：退化 → 线性度 ↑ 但增益 ↓（trade-off）
- → 同源技术：[[C4.差分放大器#4.2.3 源极退化差分对|差分对退化]]
- → 应用：[[C5.电流镜与偏置技术#5.1 基本电流镜|电流镜偏置]]
```
**结论**：**一个知识点 = 链接 + 它和别人的关系。** 把关系写下来，知识才成网。
**符号约定（照抄即可）**：
- `→` / `←` 单向依赖或应用（"A 用于 B"）
- `↔` 双向互补（"A 与 B 互补"）
- `⚡` 关键 trade-off / 设计洞察

### 第 12 页 · wikilink：把笔记焊成一张网
**素材**：`IC/CLAUDE.md`「Obsidian 双向链接」的路径规则
```
同子文件夹内：   [[笔记文件名]]  或  [[笔记文件名#标题]]
跨子文件夹：     [[子文件夹名/笔记文件名#标题]]
跨知识库：       [[IC/Razavi-RF Microelectronics/LNA|RFIC: LNA]]
```
**结论**：**链接要写全，但显示名可以短。** `|` 后面是给人看的，前面是给机器找的。
**大一能照做**：每次写到"这个概念后面还会用到"，就顺手加一个 `[[ ]]`。

### 第 13 页 · 架构不止一种：两种真实模式
**素材 A**：`IC/` —— **教材库模式**（树状，深）
```
IC/
├── CLAUDE.md
├── 知识导图.md
├── Razavi-模拟CMOS集成电路设计/   ← 一本教材一个文件夹
├── Razavi-RF Microelectronics/
├── Ludwig-RF Circuit Design/
├── 微电子工艺与封装/
└── Papers/
```
**素材 B**：`IELTS/口语语料库/` —— **扁平工具库模式**（平，浅）
```
口语语料库/
├── CLAUDE.md
├── 万能工具箱.md      ← 跨话题共用件，只写一次
├── Hometown.md        ← 一个话题一个文件，全部平铺
├── School Life.md
└── ...
```
**结论**：**树状适合"有体系的学科"，扁平适合"并列的清单"。** 选哪种取决于你的知识长得像树还是像抽屉。
**讲法**：注意 `万能工具箱.md` 那句话——"每个话题文件中不再重复收录本页已有的内容"。**去重，是靠架构解决的，不是靠记性。**

### 第 14 页 · 架构要能长大
**结论**：**加新内容时，不需要推翻重来，这才叫好架构。**
**素材**：本仓库的三种扩展方式
1. **加一本教材** → `IC/` 下新建 `作者-书名简称/`，在各自录挂上 L4 链接
2. **加一篇论文** → 进 `Papers/`，命名 `作者-年份-主题.md`
3. **加一个新领域** → 顶层新建文件夹（如 `微电子工艺与封装/` 就是这样长出来的）
**讲法**：`IC/` 里的 `Sansen-模拟集成电路设计精粹/`、`Pelgrom-ADC/` 是**预留位**——先定名字，以后有资料再填。

### 第 15 页 · 防止烂尾的三个设计
**结论**：知识库死于"没有下一步"，不死于"内容不够多"。
**素材**：本仓库真实做法
1. **留插槽**：`IC/CLAUDE.md` 的「课本插槽」写明每本教材的**路径、学习状态（🆕首次 / 🔄第二次）、当前进度**
2. **留槽位**：`## 振荡器` 这种空标题先挂着，不预建叶子节点
3. **留约定**：明确"不写的部分"（如 `❌ 课后习题（目前不覆盖）`）
**讲法**：**写下"还没做的部分"和"不做的部分"**——这让你三个月后打开仓库时，知道从哪继续。

## 第三部分：工作流 —— 怎么持续产出（第 18–26 页）

### 第 18 页 · 为什么需要"固定流程"
**结论**：**能长期坚持的，一定是流程，不是意志力。**
**讲法**：你不会每天决定"今天要不要刷牙"，因为它是流程。知识库也一样——每次学完一章，固定几个动作，不靠"今天有没有状态"。

### 第 19 页 · 本仓库的真实工作流：写笔记前的四步 ★
**素材**：`IC/CLAUDE.md`「写笔记前的上下文准备」**原文**
```
AI 在撰写新章节笔记前，应执行以下步骤：
1. 读 [[知识导图]]  → 在思维导图中定位该知识点的位置、与哪些已有概念关联
2. 读教材原文      → 从对应页数范围读取原书内容
3. 搜相关笔记      → 搜索其他子文件夹中是否有同一概念的讲解（用于跨书对比）
4. 在笔记中体现位置感 → 利用 wikilink 链接到前置概念和后续应用
```
**结论**：**第 1 步是全课最值钱的一条习惯：让 AI 动手前先看地图。**
**对比新人做法**：直接说"帮我写篇差分放大器的笔记"→ 得到一篇谁也不挨着谁的孤立文章。
**正确做法**："先读知识导图，告诉我差分放大器在哪，和谁相关，再写。"

### 第 20 页 · 写完必回填：导图自动维护 ★
**素材**：`IC/CLAUDE.md`「知识导图的自动维护规则」**原文**
```
触发时机：AI 每次完成一篇笔记的撰写或修改后，必须执行以下维护：
1. 读取 [[知识导图]]，了解已有概念树结构
2. 增量更新标题层级：
   - 引入新概念 → 在对应 L2 子域下添加 #### 概念名 + L4 链接
   - 新概念属于已有 L3 → 在已有 #### 下添加新的 L4 链接
   - 需要新建 L2/L1 → 先与用户确认
3. 添加跨域关联标注（两端各加一行 → / ↔）
4. 同一概念多本书时，追加新书的 L4 链接
```
**结论**：**"写完回填"是整个知识库的心脏。** 少了这一步，导图三个月就过期，然后你就再也不信它了。
**讲法**：注意第 2 步最后一条——**新建大层级要先问你**。这是个聪明的设计，下面会讲。

### 第 21 页 · 一次完整循环（把流程画出来）
```
   你：我要学《通信原理》第 4 章
        ↓
   AI：① 读知识导图，报告"这章在体系里的位置和关联"
        ↓
   你：确认 / 修正方向
        ↓
   AI：② 读教材原文 → ③ 搜全库有无相关笔记 → 写笔记 + wikilink
        ↓
   AI：④ 回填知识导图（新增 L4 链接 + 跨域标注）
        ↓
   你：验收（内容对不对？链接通不通？）
        ↓
   回到循环：下一章
```
**结论**：**注意中间那个"你确认"**。AI 不是全自动流水线，你是那个按确认键的人。

### 第 22 页 · 联想与贯通：让知识之间发生关系 ★
**素材**：`IC/CLAUDE.md`「AI 行为准则」
```
对每个结论，追问两个问题：
1. 为什么（Why）：物理直觉上为什么会这样？数学上为什么必然如此？
2. 然后呢（So What）：这个结论对电路设计意味着什么？后续哪一章会用到？

联想与贯通：
- 遇到与前面章节呼应的内容，用 [[子文件夹/章节名]] 链接，并用一句话点明联系
- 主动标注知识点在整个知识体系中的位置
  （如"这是模拟设计三大核心折中之一：增益-带宽-摆幅"）
- 可以将结论与 vault 内其他领域关联：[[Digital Design/...]]、[[Magnetic Theory]]
```
**结论**：**知识库的价值不来自单篇质量，来自篇与篇之间的连接。**
**大一能照做**：每学完一个概念，逼自己回答一句"它在整个课里处于什么位置"。

### 第 23 页 · 插图与附件：全库统一收口
**素材**：`IC/CLAUDE.md`「插图」流程
```
1. 从教材 images/ 定位图片
2. 复制到 System/Attachments/（重命名为可读名：书名-章节-图号.jpg）
3. 在笔记中用 ![[图片文件名.jpg]] 嵌入，可加 |宽度px
规则：同一张图只复制一次；原教材 images/ 保持不变
```
**结论**：**附件收在固定位置，只存一份。** 否则你的库会在半年内膨胀到几个 G，还全是重复图。
**补充**：给图片起**可读名**。`Pozar-C3-图3.12.jpg` 一眼认得出，`image-20260913.png` 不行。

### 第 24 页 · 除了正文，还要记什么
**结论**：知识库不只是"知识点"，**来源、时间、标签、进度同样是知识。**
**素材**：本仓库的真实做法
| 记什么 | 怎么记 | 好处 |
|---|---|---|
| 来源 | 文件名带 `作者-书名简称` + 链接显示 `Razavi: xxx` | 知道每句话的出处 |
| 时间 | front-matter（如规划书的 `date: 2026-09`） | 知道新旧 |
| 标签 | `#part1 #part2 #基础 #进阶`（IELTS 语料库） | 多维检索 |
| 进度 | 插槽里写「当前进度：第 3–5 章」 | **知道从哪继续** |
**讲法**：最后一行最重要。**"我学到哪了"是知识库里最容易丢、也最贵的信息。**

### 第 25 页 · 哪些事不要让 AI 做
**素材**：`IC/CLAUDE.md`「不做的操作」与「不要做的事」
```
导图维护层面：
❌ 不删除已有概念/链接（除非归类明显错误且用户确认）
❌ 不为每个 ### 子标题创建 #### 概念节点（只到笔记的 # / ## 级别）
❌ 不为尚未写的章节预建节点

笔记撰写层面：
❌ 不要逐句翻译教材段落
❌ 不要罗列无解释的公式
❌ 不要写"显然"、"易得"——把"为什么显然"说清楚
❌ 不要在不确定的情况下编造内容——宁可标注（此处需对照原书 X 页确认）
```
**结论**：**"不许做什么"比"要做什么"更重要。** AI 会走捷径，红线要提前划。
**讲法**：为什么"不为未写的章节预建节点"？因为**空节点会变成幻觉的温床**——AI 看到一个空标题，就会想填点什么进去。

### 第 26 页 · 版本管理：让仓库自己记账
**素材**：本仓库真实 `git log`
```
2bc16a6  vault auto-sync 2026-09-17 10:04 (study.ps1)
dd022f1  study: 自动提交 2026-09-16 14:33:11
2ac1e57  vault auto-sync 2026-09-16 13:53 (study.ps1)
```
**结论**：**每天自动提交一次，成本几乎为零，收益是"任何时刻都能回退"。**
**讲法**：AI 改文件很猛，一次改错可能毁掉一周。自动提交 = 免费的后悔药。
**大一版**：不用会 Git 命令，装 Git 插件、设个定时任务，甚至手动"每天提交一次"都行——**关键是别让改动只存在于当前状态**。

### 第 27 页 · 本部分小结
**一张卡片**：工作流五步
**读地图 → 写/整理 → 回填导图 → 你自己验收 → 自动提交**

## 第四部分：约束文件 —— 怎么让 AI 不跑偏（第 28–35 页）

### 第 28 页 · 什么是约束文件
**结论**：约束文件 = **写给 AI 的规章制度**。它不说"要做什么"，只规定"怎么做、什么绝对不做"。
**素材**：本仓库的 `CLAUDE.md`，放在每个知识库文件夹根部
**讲法**：你不可能每次开新对话都从头讲一遍"我的文件夹怎么命名、公式怎么写、不要写废话"。所以要**写下来，放在 AI 一定会读到的地方**。

### 第 29 页 · 为什么 AI 特别需要它
**结论**：AI 有三个天然毛病——**没有记忆、倾向讨好、爱编造**。
| 毛病 | 后果 | 约束文件怎么治 |
|---|---|---|
| 没有记忆 | 每次重讲一遍 | 写进文件，自动加载 |
| 倾向于讨好你 | 你说什么它都说"好的" | 明确规定「不要做的事」 |
| 爱编造 | 编公式、编文献、填空节点 | 强制"标注待确认" |
**讲法**：这三条不是 AI 的缺陷，是它的**本性**。约束文件就是在给本性装护栏。

### 第 30 页 · 约束的三层结构 ★
**素材**：本仓库真实的三层落点
```
第一层  Vault 级        根目录            管"整个仓库的铁律"
第二层  学科/文件夹级   IC/CLAUDE.md      管"这个学科的规矩"
                       Communication/CLAUDE.md
                       Digital Design/CLAUDE.md
                       Magneticelectro Theory/CLAUDE.md
                       IELTS/口语语料库/CLAUDE.md
第三层  具体项目级      竞赛文档/ 2026嵌赛/  管"这个项目的规范"
```
**结论**：**越往下越具体。全局规则别塞进学科文件，学科细节别污染全局。**
**讲法**：AI 读约束的顺序也是从全局到局部——**放对位置比写得多更重要**。

### 第 31 页 · 一份真实约束文件拆解 ★
**素材**：`IC/CLAUDE.md` 的骨架（现场投屏局部）
| 章节 | 作用 | 给 AI 的信息 |
|---|---|---|
| 项目概述 / 核心理念 | 这是什么、为什么这样组织 | **定位** |
| 文件夹结构 + 规则 | 命名规范、放哪、怎么引用 | **地图** |
| 知识导图 L0–L4 体系 | 索引中枢的层级约定 | **结构** |
| 导图自动维护规则 | 写完笔记必须回填 | **流程** |
| 笔记撰写通用标准 | 深度原则、语言风格、标题层级、数学准则、术语规范 | **质量** |
| AI 行为准则 | 追问 Why/So What、写前准备、不要做的事 | **纪律** |
| 课本插槽 | 每本教材的路径/状态/风格/进度 | **上下文** |
**结论**：一份好约束，把 **定位、地图、结构、流程、质量、纪律、上下文** 全交代了。
**讲法**：注意最后一项——连教材的**绝对路径、学习状态、当前进度**都写了。AI 不用问就知道去哪找、从哪继续。这就是"约束文件"和"需求文档"的区别。

### 第 32 页 · 约束必须可判定：正例 vs 反例 ★
**素材**：`IC/CLAUDE.md`「语言风格」条款
```
❌ 模糊约束（AI 无法执行）
   "写得专业一点"   "注意质量"   "要准确"   "简洁一些"

✅ 可执行约束（AI 能照做）
   "不要写过渡句和引导句——'一个容易忽略的事实是''值得深思的是'
    这类句子直接删掉"
   "同一个观点只解释一遍——在第一遍解释时就找准角度，一次说透"
   "重要术语首次出现时，中文 + 英文/符号并列：
    跨导（transconductance, $g_m$）"
   "标题层级：'#' 章级小节，'##' 子节，'###' 具体知识点，不做更深嵌套"
```
**结论**：**约束必须是可判定的。能写出"违反了长什么样"，AI 才能遵守。**
**讲法（本场最实用的一页）**：**现场训练**——把"写好一点"翻译成能判定的规则。这是学生回去立刻能用的技能。

### 第 33 页 · 大一版约束文件模板（照抄）
```markdown
# 我的知识库 — 规则

## 这是什么
我的大学课程知识库。每个学科一个文件夹，每个学科一份 `知识导图.md`。

## 文件夹规则
- 学科文件夹用中文名；每份资料来源一个子文件夹，命名 `作者-书名简称`
- 图片统一放 `System/Attachments/`，命名 `书名-章节-图号.jpg`
- 论文放 `Papers/`，命名 `作者-年份-主题.md`

## 导图规则
- 层级：# 根 → ## 知识域 → ### 子域 → #### 概念 → - [[链接]]
- 每写完一篇笔记，必须回填导图：新增 L4 链接 + 跨域标注
- 新增 L1/L2 层级前必须先问我
- 不删除已有链接；不为未写的章节预建节点

## 笔记规则
- 结论直接说，不写过渡句和引导句
- 重要术语首次出现：中文 + 英文并列
- 不确定的内容标注「需确认」，不要编造

## 不要做的事
❌ 不要罗列无解释的公式    ❌ 不要写"显然""易得"
❌ 不要逐句翻译教材        ❌ 不要在不确定时编造内容
```
**结论**：**约 25 行，覆盖了 80% 的日常问题。** 今天回去就能用。

### 第 34 页 · 约束文件是活文件
**结论**：**约束不是一次写完的，是被"踩坑"踩出来的。**
**素材**：本仓库的真实体量——`IC/CLAUDE.md` 418 行、`Digital Design/CLAUDE.md` 373 行。
**讲法**：里面大量条款（比如插图流程从"占位标注"改成"直接嵌入"）都是**吃过亏之后加上的**。
**给大一的建议**：起步 25 行就够。**每次 AI 做错一件事，就往约束文件里加一条。** 三个月后它会变成你最值钱的资产。

### 第 35 页 · 本部分小结
**一张卡片**：约束三层 + 一条铁律
**全局规则 → 学科规则 → 项目规则**，且**每条都必须可判定**。

## 第五部分：落地（第 36 页）

### 第 36 页 · 大一新生的 7 条行动清单 ★
1. **今晚就建骨架**：两个学科文件夹 + 一份 `知识导图.md` + `System/Attachments/`
2. **先定命名规则再动手**：`作者-书名简称`，写进约束文件
3. **每篇笔记写完，必须回填导图**——这一条做到，库就活了
4. **让 AI 先读地图再动笔**："先读知识导图，告诉我这东西在哪、和谁相关，再写"
5. **约束文件从 25 行起步**，每次 AI 出错就加一条
6. **每天自动提交一次**（Git），别让改动只存在于"当前状态"
7. **插图只存一份**，放在固定位置，起可读的名字

**一句话收尾**：
> **架构决定你的笔记能不能连成网，工作流决定这个库能不能活过三个月，约束文件决定你半年后还敢不敢打开它。**
